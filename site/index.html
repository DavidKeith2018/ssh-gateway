02 / RECOMMENDED DEPLOYMENT

Deploy the gateway separately.
Isolate original credentials from AI.

Run the gateway on a separate machine whose files AI cannot directly read. Give AI only the relay connection to the target server.

Isolate files and management access

Do not give AI terminal access to the gateway host or gateway management credentials. Keep data directories, databases, master keys, and backups inaccessible to AI, including through shared folders.

Pair encryption with deployment isolation

AI can learn storage locations and decryption logic from source code. Without a master password, reading both the database and master key may expose original credentials. A master password protects locked data, but privileged AI may still read an unlocked process’s memory. Running on the same machine is convenient; a separate deployment makes access isolation easier.

03 / FEATURES

From AI access to everyday management.

Manage AI access with dedicated credentials and familiar SSH tools and web terminals.

01

Keep original credentials in the gateway

AI uses a separate relay username and password, without receiving original server passwords or private keys. Each machine supports multiple relay credentials bound to target login accounts.

02

Restrict access by source

Allow IPs or subnets per target. Global single-IP grants can expire after up to 30 days. An allowed source still needs valid relay credentials.

03

Revoke access when needed

Reset or disable relay credentials, or disable or delete a target. Affected connections usually close within about a second. Relay credentials do not expire automatically.

04

Manage servers together

Use password or private-key authentication and verify host fingerprints. Administrators can grant users web workspace access by machine or tag.

05

Terminals, files, and port mappings

Open terminals, manage files and notes in your browser. Administrators can configure local and reverse port mappings. Logs record connections and configuration changes.

06

Deploy separately to isolate data

Original passwords and private keys are encrypted. Enable an optional master password in Security Settings to require manual unlocking after each restart. Deploy separately and isolate management access and backups.

05 / GET STARTED

Download, launch, and connect.

Choose a package for your system, then install or extract it and launch.
No Go, Node.js, or source compilation is required.

  1. Open Downloads and choose your operating system and architecture.
  2. For Windows portable, extract the ZIP and run the app. Install other desktop packages, or extract the Linux server archive and run the command shown here.
  3. Set a password when prompted on desktop. For the server, open http://127.0.0.1:8080 and use the initial administrator password from the startup log.
  4. Add a server, verify its fingerprint, and configure relay credentials and allowed source IPs to open a terminal.

Know the boundaries before you start.

Actual source IPAccess rules use the TCP peer address. Connect directly over built-in HTTPS to distinguish clients. Tunnels and reverse proxies can change the source address seen by the gateway.

Complete backupsStop the service and back up the entire data directory. You need both the database and encryption key. When enabled, the corresponding master password is also required for recovery. Protect older backups containing unprotected master keys.

Scope of accessAI operations use the bound target account’s permissions. Protect relay credentials: anyone with valid credentials and an allowed source can connect. No command approval, automatically expiring links, or session recording.
